# QuickTix: a mini support-ticket tracker

A small app with just enough surface area (auth, CRUD, filtering, validation) to make the E2E suite and CI report worth showing off.

## The app

- **MongoDB + Mongoose**: `users` and `tickets` (title, description, priority, status, owner)
- **Express + Node**: JWT login, `/api/tickets` CRUD, `/api/health`, and a test-only `/api/test/reset` endpoint that wipes and seeds the DB
- **Angular** (standalone components): login page, ticket list with status filter, create/edit form, delete with confirm
- **One process in production**: Express serves the built Angular `dist/`, so Playwright and CI only have to start one server

```
quicktix/
├─ client/        # Angular
├─ server/        # Express + Mongoose
├─ e2e/           # Playwright tests + auth.setup.ts
├─ playwright.config.ts
└─ .github/workflows/ci.yml
```

## Playwright suite

Around 8 to 10 tests is plenty:

1. **Setup project**: logs in once and saves `storageState`, so other tests skip the login UI
2. Login fails with bad credentials and shows an error
3. Create a ticket and see it in the list
4. Validation: an empty title shows an inline error
5. Edit a ticket's status from Open to Resolved
6. Filter by status shows only matching tickets
7. Delete a ticket after the confirm dialog
8. Unauthenticated access to `/tickets` redirects to `/login`
9. API-level test using Playwright's `request` fixture (401 without a token)
10. Tag 2 or 3 of these `@smoke` for fast PR checks

A `beforeEach` that calls `/api/test/reset` keeps the tests independent.

## Key config

```ts
// playwright.config.ts
export default defineConfig({
  testDir: './e2e',
  retries: process.env.CI ? 1 : 0,
  reporter: [
    ['list'],
    ['html', { open: 'never' }],
    ['junit', { outputFile: 'results/junit.xml' }],
  ],
  use: {
    baseURL: 'http://localhost:3000',
    trace: 'on-first-retry',
    screenshot: 'only-on-failure',
    video: 'retain-on-failure',
  },
  webServer: {
    command: 'npm start --prefix server',
    url: 'http://localhost:3000/api/health',
    reuseExistingServer: !process.env.CI,
  },
  projects: [
    { name: 'setup', testMatch: /auth\.setup\.ts/ },
    {
      name: 'chromium',
      use: { ...devices['Desktop Chrome'], storageState: '.auth/user.json' },
      dependencies: ['setup'],
    },
  ],
});
```

```yaml
# .github/workflows/ci.yml
name: CI
on:
  push: { branches: [main] }
  pull_request:

jobs:
  e2e:
    runs-on: ubuntu-latest
    services:
      mongo:
        image: mongo:7
        ports: ['27017:27017']
    env:
      MONGO_URI: mongodb://localhost:27017/quicktix_test
      JWT_SECRET: ci-only-secret
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 22, cache: npm }
      - run: npm ci
      - run: npm run build --prefix client
      - run: npx playwright install --with-deps chromium
      - run: npx playwright test
      - if: always()
        uses: actions/upload-artifact@v4
        with:
          name: playwright-report
          path: |
            playwright-report/
            results/
          retention-days: 14
```

I've used `v4` action tags here, so check for newer majors when you set it up.

## Report generation and verification

- **HTML report** (built into Playwright): uploaded as an artifact on every run, pass or fail
- **Traces, screenshots and video** on failure, viewable inside the HTML report
- **JUnit XML**: feed it to a test-summary action to get pass/fail tables in the PR or in `$GITHUB_STEP_SUMMARY`
- **GitHub Pages deploy** (second job, `needs: e2e`, `if: always()`): publishes the latest report at a stable URL you can link from the README
- **Branch protection**: require the `e2e` check to pass before merging, which is the "verification" gate

## Tips to stay on time

- Skip Angular styling libraries. Plain CSS is enough, since the point is testability.
- Add `data-testid` while building the UI so you don't retrofit selectors later.
- Get a green CI run with one trivial test by minute 60, then grow the suite. That way pipeline problems surface early instead of at the end.
