1. EXECUTIVE SUMMARY & ARCHITECTURAL OVERVIEW
================================================================================
QuickTix is a focused, production-grade MEAN-stack support ticket application 
specifically engineered to demonstrate end-to-end testing excellence, test 
isolation, and CI/CD reporting with Playwright.

Key architectural characteristics:
- Single-Process Production Serving: Express acts as both the REST API backend
  and the static host for Angular's compiled production bundle (`dist/`). This 
  drastically simplifies Playwright's `webServer` orchestration locally and in CI.
- Deterministic Isolation via /api/test/reset: A dedicated, highly secured test
  endpoint wipes and seeds MongoDB with fixed ObjectId entities and timestamps.
- Zero Test Interference: Configured with `workers: 1` and sequential runs 
  (`fullyParallel: false`) to guarantee data integrity across test wipes.
- Cross-Platform Windows & Linux Resilience: Avoids bash-only inline environment
  variable commands (e.g. `NODE_ENV=test npm start`), delegating environment 
  configuration to Playwright's `webServer.env`.
- Fork-Safe CI/CD: Uses throwaway CI secrets injected at job level, avoiding 
  broken builds on open-source fork pull requests.

2.2. Seed Data & State Reset Specification
--------------------------------------------------------------------------------
Endpoint: POST /api/test/reset
Access Policy:
  1. Route is mounted ONLY when `NODE_ENV === 'test'`. In production or dev, it 
     does not exist and returns HTTP 404 (Not Found).
  2. The handler checks the active Mongoose database name: refuses to execute and 
     aborts with 403/500 if the database name does not end in `_test`.
  3. Bcrypt password hashing is performed ONCE at module load (cost factor 4) 
     to ensure reset calls complete in under 20ms.

Fixed Entities Seeded on Reset:
- User 1 (Primary QA User):
  * _id: "000000000000000000000001"
  * Email: "qa.user@quicktix.test"
  * Password: "Passw0rd!test" (hashed with cost 4)
- User 2 (Foreign Owner User):
  * _id: "000000000000000000000002"
  * Email: "other.user@quicktix.test"
  * Password: "Passw0rd!test"
- Tickets for User 1:
  * Ticket 1: Title: "Fix login button styling", Status: "Open", Priority: "High",
              CreatedAt: T - 3 days, _id: "100000000000000000000001"
  * Ticket 2: Title: "Update documentation footer", Status: "Open", Priority: "Low",
              CreatedAt: T - 2 days, _id: "100000000000000000000002"
  * Ticket 3: Title: "Investigate memory leak", Status: "In Progress", Priority: "Medium",
              CreatedAt: T - 1 day, _id: "100000000000000000000003"
  * Ticket 4: Title: "Setup automated backups", Status: "Resolved", Priority: "Low",
              CreatedAt: T, _id: "100000000000000000000004"
- Ticket for User 2:
  * Ticket 5: Title: "Foreign user secret issue", Status: "Open", Priority: "Urgent",
              CreatedAt: T, _id: "100000000000000000000005"
  * Strict Rule: Must NEVER appear in User 1's list (Owner Scoping).

Response Contract:
  HTTP 200 OK:
  {
    "status": "reset_complete",
    "users": ["000000000000000000000001", "000000000000000000000002"],
    "tickets": ["100000000000000000000001", "100000000000000000000002", "100000000000000000000003", "100000000000000000000004", "100000000000000000000005"]
  }

2.3. Authentication & Storage State Mechanics
--------------------------------------------------------------------------------
- Algorithm & Expiry: HMAC SHA-256 JWT, signed with `JWT_SECRET`, valid for 24h.
- Storage Target: Stored in browser `localStorage` under the exact key `token`.
  * Rationale: Playwright's `storageState` persists cookies and `localStorage`. 
    `sessionStorage` is NOT captured by storageState and must NOT be used.
- Auth State Survival Across Resets:
  Because User 1 retains the deterministic ObjectId `000000000000000000000001` and
  `JWT_SECRET` remains constant across test execution, the token generated in 
  `auth.setup.ts` remains completely valid after every single `/api/test/reset`.
- Angular Interceptor:
  Extracts `localStorage.getItem('token')` and appends `Authorization: Bearer <token>`.
- Logged-Out Test Overrides:
  Tests validating 401s or login redirects explicitly override storage state:
  `test.use({ storageState: { cookies: [], origins: [] } });`

2.4. REST API & Data Validation Contract
--------------------------------------------------------------------------------
Base URL: /api
Health Probe: GET /api/health
  - Returns HTTP 200 `{ status: "ok", mongo: "connected" }` ONLY when Mongoose 
    connection state is 1 (connected). Returns 503 if disconnected.

Auth Routes:
  - POST /api/auth/login
    * Payload: `{ email, password }`
    * 200 OK: `{ token: "..." }`
    * 401 Unauthorized: `{ error: "Unauthorized", message: "Invalid email or password" }`

Ticket Routes:
  - GET /api/tickets?status=
    * Filter: Optional query parameter `status` (`Open`, `In Progress`, `Resolved`, `Closed`).
    * Owner Scoping: Returns only tickets where `owner === req.user.id`.
    * Sorting: Deterministic descending order by creation date (`sort({ createdAt: -1 })`).
    * 200 OK: `[ { _id, title, description, priority, status, owner, createdAt, updatedAt } ]`
  - POST /api/tickets
    * 201 Created: returns created ticket object.
  - PUT /api/tickets/:id
    * Updates title, description, priority, or status.
    * 200 OK: returns updated ticket object.
    * 404 Not Found: ticket does not exist or belongs to another owner.
  - DELETE /api/tickets/:id
    * 204 No Content.
    * 404 Not Found: ticket does not exist or belongs to another owner.

Field Validation Rules (Client and Server enforced):
  - Title: Required, trimmed string, 3 to 100 characters.
  - Description: Optional string, maximum 500 characters.
  - Priority: Required enum: `Low` | `Medium` | `High` | `Urgent` (Default: `Medium`).
  - Status: Required enum: `Open` | `In Progress` | `Resolved` | `Closed` (Default: `Open`).

Standardized Error Payloads:
  - 400 Bad Request:
    `{ "error": "ValidationError", "message": "Title must be between 3 and 100 characters" }`
  - 401 Unauthorized:
    `{ "error": "Unauthorized", "message": "Valid token required" }`
  - 404 Not Found:
    `{ "error": "NotFound", "message": "Ticket not found" }`

2.5. UI Component Contract & data-testid Dictionary
--------------------------------------------------------------------------------
Strict Locator Convention:
- Flat kebab-case identifiers (`<area>-<element>`).
- NO dynamic values inside `data-testid` (e.g. no `ticket-row-12345`).
- Rows are identified via `data-testid="ticket-row"` with an auxiliary attribute
  `data-ticket-id="<id>"`. Playwright scopes rows using:
  `page.getByTestId('ticket-row').filter({ hasText: 'Ticket Title' })`
- Form dropdowns use native HTML `<select>` elements.
- Validation and server error messages must include `role="alert"`.
- Deletion confirmation uses a custom modal (never `window.confirm`).

2.6. Express 5 Static Serving & SPA Fallback Contract
--------------------------------------------------------------------------------
Critical Express 5 Compatibility:
Express 5 breaks when using legacy wildcard route declarations like `app.get('*', ...)`.
The server must register static files and SPA fallback as follows:

```typescript
const clientDist = process.env.CLIENT_DIST || path.resolve(__dirname, '../../client/dist/browser');

// Startup guard: Fail fast if frontend build is missing
if (!fs.existsSync(path.join(clientDist, 'index.html'))) {
  console.error(`FATAL: Frontend build not found at ${clientDist}. Run client build first.`);
  process.exit(1);
}

// Serve static assets (hashed JS, CSS, images)
app.use(express.static(clientDist));

// SPA Catch-all middleware: skips /api, disables caching on index.html
app.use((req, res, next) => {
  if (req.path.startsWith('/api')) {
    return next();
  }
  res.setHeader('Cache-Control', 'no-cache, no-store, must-revalidate');
  res.sendFile(path.join(clientDist, 'index.html'));
});
```

TASK 1: EXPRESS API, MONGOOSE MODELS, VALIDATION & RESET PROBE (0:10 - 0:40)
--------------------------------------------------------------------------------
Goal: Build robust backend API with strict validation, owner-scoped CRUD, 
readiness probe, and production-guarded reset endpoint.

Subtasks:
1.1. Architecture Decoupling (`app.ts` vs `index.ts`):
     - `server/src/app.ts`: Instantiates Express, configures JSON parser, CORS,
       registers API routes, static file serving, and error handling. Exports `app`.
     - `server/src/index.ts`: Connects Mongoose to `MONGO_URI`, listens on `PORT`,
       performs startup checks (verifying `index.html` presence in production).
1.2. Mongoose Schemas & Models:
     - `server/src/models/User.ts`:
       * Fields: `email` (string, unique, lowercase), `password` (hashed string), `role`
     - `server/src/models/Ticket.ts`:
       * Fields: `title` (3-100 chars), `description` (max 500 chars),
         `priority` (enum: Low, Medium, High, Urgent), `status` (enum: Open, In Progress,
         Resolved, Closed), `owner` (ObjectId ref User), `createdAt`, `updatedAt`.
       * Compound index on `{ owner: 1, createdAt: -1 }`.
1.3. Authentication System:
     - `POST /api/auth/login`: Validates credentials with `bcrypt.compare`, signs JWT
       (24h duration) containing `{ id: user._id, email: user.email }`.
     - Middleware `server/src/middleware/auth.ts`: Verifies Bearer token. Returns 401
       if missing/invalid. Attaches decoded payload to `req.user`.
1.4. Owner-Scoped Ticket CRUD Routes:
     - `GET /api/tickets`: Filters by `owner: req.user.id` and optional query `status`.
       Sorts by `createdAt: -1`.
     - `POST /api/tickets`: Validates payload (title 3-100 chars, priority/status enums),
       assigns `owner: req.user.id`, returns 201.
     - `PUT /api/tickets/:id`: Finds by `_id: id, owner: req.user.id`. Updates and returns 200.
       Returns 404 if not found or unauthorized owner.
     - `DELETE /api/tickets/:id`: Finds by `_id: id, owner: req.user.id`. Deletes and returns 204.
       Returns 404 if not found or unauthorized owner.
1.5. Health Probe:
     - `GET /api/health`: Checks `mongoose.connection.readyState === 1`.
       Returns 200 `{ status: "ok", mongo: "connected" }` or 503.
1.6. Test Reset Endpoint (`/api/test/reset`):
     - Mounts in `app.ts` strictly within `if (process.env.NODE_ENV === 'test')`.
     - Inside handler: Check `mongoose.connection.name.endsWith('_test')`.
     - Precomputes bcrypt hash once at module load (`bcrypt.hashSync('Passw0rd!test', 4)`).
     - Execution sequence:
       1) `await User.deleteMany({})`
       2) `await Ticket.deleteMany({})`
       3) `await User.insertMany([User1, User2])` with fixed ObjectIds
       4) `await Ticket.insertMany([Ticket1..Ticket5])` with fixed ObjectIds and dates
       5) Returns 200 with IDs list.
1.7. Static File & SPA Fallback:
     - Implement Express 5 compatible middleware (as defined in Contract 2.6).

Verification Milestone 1:
- Execute curl/bash validation script testing:
  1) `GET /api/health` -> 200
  2) `POST /api/auth/login` (bad credentials) -> 401
  3) `POST /api/auth/login` (User 1 credentials) -> 200 `{ token }`
  4) `GET /api/tickets` (with token) -> 200 with 4 tickets
  5) `POST /api/tickets` with empty title -> 400 ValidationError
  6) In production mode (`NODE_ENV=production`), `POST /api/test/reset` -> 404 Not Found.

4. CRITICAL GOTCHAS, EDGE CASES & CROSS-PLATFORM PRECAUTIONS
================================================================================

1. Windows OS & Inline Environment Variables:
   * Issue: Inline scripts like `NODE_ENV=test npm start` fail on Windows CMD/PowerShell.
   * Solution: Never use inline syntax in `package.json` or `playwright.config.ts`.
     Declare environment variables directly inside the `webServer.env` object in
     `playwright.config.ts`.

2. Express 5 Route Matching:
   * Issue: `app.get('*', ...)` throws a route parsing error on Express 5.
   * Solution: Use standard middleware `app.use((req, res, next) => { ... })`
     and guard against `/api` paths with `if (req.path.startsWith('/api')) return next();`.

3. Angular Distribution Path Discrepancy:
   * Issue: Angular 17+ defaults to `dist/<project-name>/browser` rather than `dist/browser`.
   * Solution: Check build output after first build; configure `CLIENT_DIST` environment
     variable with a robust fallback; verify index.html exists at server startup.

4. Bcrypt Performance Bottleneck during Resets:
   * Issue: Hashing passwords with default rounds (10+) inside `/api/test/reset` adds
     200ms-500ms delay per test.
   * Solution: Compute hash ONCE at module load using cost factor 4. Reset execution drops
     to under 15ms.

5. StorageState Token Invalidation:
   * Issue: If `/api/test/reset` generates new dynamic user IDs on wipe, stored JWT
     tokens become orphaned and cause unexpected 401 errors.
   * Solution: User 1 ALWAYS retains ObjectId `000000000000000000000001` and `JWT_SECRET`
     remains constant across test runs.

6. GitHub Secrets in Fork Pull Requests:
   * Issue: Workflows triggered by fork pull requests do not have access to GitHub Secrets,
     causing ${{ secrets.JWT_SECRET }} to evaluate to empty.
   * Solution: Set non-sensitive test values (`ci-only-secret`) directly in workflow `env:`.
     Server refuses insecure secrets strictly when `NODE_ENV === 'production'`.

7. MongoDB Service Container Timing:
   * Issue: Spawning MongoDB as a Docker container does not mean it is immediately ready
     to accept connections.
   * Solution: Implement service container `--health-cmd` with `mongosh` ping, combined
     with server readiness probe at `/api/health`.

6. CI/CD PIPELINE BLUEPRINT (GITHUB ACTIONS)
================================================================================

```yaml
name: CI
on:
  push:
    branches: [main]
  pull_request:

concurrency:
  group: ${{ github.workflow }}-${{ github.ref }}
  cancel-in-progress: ${{ github.ref != 'refs/heads/main' }}

permissions:
  contents: read

jobs:
  e2e:
    runs-on: ubuntu-latest
    timeout-minutes: 10
    services:
      mongo:
        image: mongo:7
        ports: ['27017:27017']
        options: >-
          --health-cmd "mongosh --quiet --eval 'db.runCommand({ping:1}).ok'"
          --health-interval 5s
          --health-timeout 5s
          --health-retries 10
    env:
      MONGO_URI: mongodb://localhost:27017/quicktix_test
      JWT_SECRET: ci-only-secret
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: npm
          cache-dependency-path: |
            package-lock.json
            client/package-lock.json
            server/package-lock.json
      - run: npm ci
      - run: npm ci --prefix client
      - run: npm ci --prefix server
      - run: npm run build --prefix client
      - run: npx playwright install --with-deps chromium
      - run: npx playwright test
      - if: always()
        uses: test-summary/action@v2
        with:
          paths: results/junit.xml
      - if: always()
        uses: actions/upload-artifact@v4
        with:
          name: playwright-report
          path: |
            playwright-report/
            results/
          retention-days: 14

  publish-report:
    needs: e2e
    if: ${{ !cancelled() && github.event_name == 'push' }}
    runs-on: ubuntu-latest
    permissions:
      pages: write
      id-token: write
    environment:
      name: github-pages
      url: ${{ steps.deploy.outputs.page_url }}
    steps:
      - uses: actions/download-artifact@v4
        with:
          name: playwright-report
          path: report
      - uses: actions/upload-pages-artifact@v5
        with:
          path: report/playwright-report
      - id: deploy
        uses: actions/deploy-pages@v4
```
