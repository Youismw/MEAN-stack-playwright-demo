API and behaviour

POST /api/auth/login returns 200 {token}, or 401 for bad credentials.
GET /api/tickets?status= returns own tickets, sorted by createdAt descending, with no pagination. POST returns 201, PUT /:id returns 200, and DELETE /:id returns 204.
Validation runs on both client and server:
Title is required, trimmed, 3 to 100 characters.
Description is optional, up to 500 characters.
Priority is Low, Medium, High or Urgent (default Medium).
Status is Open, In Progress, Resolved or Closed (default Open).
Errors: 400 {error:"ValidationError", message}, 401 {error:"Unauthorized", message:"Valid token required"}, 404 for a missing or foreign ticket.
The Angular interceptor sends the Bearer token, and the router guard redirects to /login.
Express serves CLIENT_DIST and an SPA fallback (any non-/api path returns index.html, sent no-cache). This works regardless of NODE_ENV. The server exits at boot if index.html is missing.
The list spinner shows on every fetch. Tests should assert on row counts, not the spinner alone.

Gotchas to handle up front
Angular output path. The answers disagree: client/dist/browser versus Angular's usual client/dist/<project>/browser. After your first build, run ls client/dist/*/browser and set that as the CLIENT_DIST default. The boot-time index.html check will catch a wrong path.
Express 5. The app.get('*', …) fallback shown in the Q&A throws on Express 5, which is what a fresh npm install express gives you. Use a plain app.use((req,res,next)=>…) fallback that skips /api.
Action versions. I couldn't confirm the newest majors for checkout, setup-node or upload-artifact, so I kept @v4. Add a .github/dependabot.yml for the github-actions and npm ecosystems so bumps arrive as PRs. I did find that upload-pages-artifact is now at v5.0.0, which moved to upload-artifact v7. I only saw deploy-pages listed at v4, so check it doesn't have a newer major. If the Pages steps fail, upload-pages-artifact@v3 is the older documented pairing with deploy-pages@v4. 
github
Pages setup. Set Settings → Pages → Source to "GitHub Actions". The deploy job needs pages: write and id-token: write permissions and the github-pages environment. Private repos may need a paid plan for Pages. 
github
Playwright pin. One release tracker listed 1.61.1 as the latest version as of July 2026. Install the current version and let the lockfile pin it. 
versio
Branch protection. The e2e check only appears in the picker after it has run once, so do this last.
Local reuse. reuseExistingServer can attach to a dev server that isn't in test mode. The reset fixture's clear failure message and the _test DB guard cover this.
